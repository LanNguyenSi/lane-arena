Pilot, 10 and 11 October 2026

Lane Arena: local model vs. Claude and GPT

Two real tickets, six implementers, isolated clones, a blind review and hidden tests.

The question

Can a local open-weight model keep up as an implementer?

Background

Today the local lane takes on tasks that would otherwise go to the mid-tier Claude implementer. Security-critical and hard work stays with Claude.

Goal of the pilot

Build a repeatable harness and deliver a first comparison on one medium and one hard task.

The tasks

Two real open tickets

M: Role-dependent controls

Frontend (React/Next). Buttons the server rejects with 403 should be hidden for MEMBER and VIEWER, or disabled with a reason. Clear acceptance criteria, typical lane territory.

H: Reserved usernames

Backend (Express/Prisma), security. The service-account usernames should live in one constant and be blocked at registration. The traps: letter case after normalisation, invite codes, and a test that only runs with a database.

Rules

Isolation and fair scoring

Isolation

  • Own repository clone per participant, without a remote
  • Same base commit, own dependencies
  • Strictly sequential, never in parallel

Scoring

  • Fresh Opus reviewer per round, blinded by a random label
  • Hidden tests, frozen beforehand; the required cases fail on the base state
  • Passed = the reviewer accepts, at most 3 rounds

Effort

Effort was not evenly distributed

Claude: medium

--bare ignores the user settings (xhigh). The default effort: medium was sent, for the reviewer too. Proven by request capture.

Lane: xhigh

Without a variant, opencode sends no effort, so the chat-template default applies (xhigh). Thinking is on, but opencode does not count the reasoning tokens.

Codex: model default

Sol 6.1 at low, Luna 6 at medium (per the model cache, deliberately not pinned). The reasoning tokens match.

Observations

What the review and a follow-up measurement showed

Only the lane keeps an existing database test green

An existing database test expects 409. Measured afterwards, only the lane keeps it green. Opus, Haiku, Sol and Luna break it, and the review still accepted three of them. Sonnet changed the expectation to 400 without the approval the reviewer's suggestion required.

Fast is not the same as done

Luna 6 was among the fastest on M with 33 seconds, just behind Sonnet (32 s), but failed on H after three rounds. The lane was the slowest everywhere and passed both tasks in round 1.

Docs drove the review rounds

Everyone implemented the required block. The mediums on H were almost all about line references in the repository's knowledge base, the changelog and docs statements. Luna 6 failed on exactly this three times.

Limits

What the pilot does not show

  • n = 2 tasks
  • Uneven effort (lane xhigh, Claude and Luna medium, Sol low)
  • Reviewer one tier below production
  • Hidden tests too easy, everyone passed
  • One review per solution, noise unmeasured
  • Review only partially blind
  • Local verification without database tests
Conclusion

Slower, but in this pilot not worse

Today

The rule "lane = mid-tier implementer" is supported. One good result is not enough to relax it for security-critical tasks.

Next run

  • More tasks
  • Pin the effort for everyone, reviewer at high
  • Two reviews per diff, sharper hidden tests
